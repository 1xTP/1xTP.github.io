### 1. Overview
This challenge involved exploiting an unauthenticated remote code execution vulnerability in LangFlow to gain an initial shell. After pivoting to a local user via credentials found in a configuration file, an internal MCP AI Tool Registry was discovered. By forging an unsigned JWT, administrative access was gained to the registry, allowing the execution of a reverse shell inside a Kubernetes pod. Privilege escalation was achieved by leveraging `node/proxy` permissions to interact with the Kubelet API and execute commands within a privileged container that had the host's root filesystem mounted.

### 3. Foothold
LangFlow version `1.8.2` is vulnerable to an unauthenticated remote code execution attack due to the `POST /api/v1/build_public_tmp/{flow_id}/flow endpoint` allowing unauthenticated users to build public flows when the optional data parameter is supplied.

To exploit this, I first needed to find a valid `flow_id`. Since I couldn't log in to the LangFlow service, I went back the original `fireflow.htb` website. Taking a closer look at the landing page, I noticed a `Open Agent` button. Upon clicking it, I noticed the URL had leaked the flow_id:
```
https://flow.fireflow.htb/playground/7d84d636-af65-42e4-ac38-26e867052c25
```

Since the configuration file stated that 1 endpoint required the admin role and that the `none` algorithm was supported, I could craft an unsigned token and inject the `admin` role:
```
import base64, json  
def b64url(data):  
    return base64.urlsafe_b64encode(data).rstrip(b'=').decode()  
header = b64url(json.dumps({"alg": "none", "typ": "JWT"}).encode())  
payload = b64url(json.dumps({"sub": "attacker", "role": "admin"}).encode())  
token = f"{header}.{payload}."  
print(token)
```

### 5. Conclusion
Initial access was gained by identifying an exposed LangFlow service on a subdomain and exploiting a known unauthenticated remote code execution vulnerability (CVE-2026-33017) using a leaked `flow_id`. This provided a reverse shell as the `www-data` user, where a `.env` file was found containing a password that was reused by the `nightfall` user for SSH access.

During privilege escalation enumeration, an internal MCP server configuration was found containing credentials. These were used to obtain a JWT, which was then manipulated to bypass authentication via the `none` algorithm. With the forged admin token, a malicious tool was registered and triggered, resulting in a shell inside a Kubernetes pod as the `mcp` user. Finally, Kubernetes API enumeration revealed `node/proxy` permissions, which were used to find a privileged `node-exporter` pod and execute a command through the Kubelet `/exec` endpoint to read the root flag directly from the mounted host filesystem.
